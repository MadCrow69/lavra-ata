# Plano 02 — Biblioteca `@lavra/pii-br`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** biblioteca TypeScript sem dependências que detecta identificadores pessoais brasileiros, troca por marcadores, reidrata e valida a saída de um LLM.

**Architecture:** detectores declarativos (regex + validação de DV + exigência de contexto) alimentam `detect()`, que resolve sobreposições por posição e precedência. `mask()` usa um `MaskMap` serializável (o mesmo valor normalizado → o mesmo marcador). `unmask()` e `validateOutput()` operam sobre esse mapa.

**Tech Stack:** TypeScript (ESM), Vitest. Zero dependências de runtime.

**Spec:** `docs/superpowers/specs/2026-10-20-lavra-design.md` (seção 6)

**Branch/PR:** `feat/02-pii-br` → PR "feat(pii-br): biblioteca de dados pessoais brasileiros".

## Global Constraints

- Zero dependências de runtime; ESM; funciona em navegador e Node (sem `Buffer`, `fs`, `crypto` do Node).
- Marcador canônico: `[TIPO_N]`, tipo em maiúsculas sem acento, N a partir de 1 por tipo. Tipos: `CPF`, `CNPJ`, `EMAIL`, `TELEFONE`, `CEP`, `PLACA`, `PIS`, `RG`, `CARTAO`.
- O mesmo valor normalizado recebe sempre o mesmo marcador dentro de um `MaskMap`.
- Nomes de pessoas, endereços e datas **não** são detectados (o README diz isso).
- `MaskMap` é JSON puro (vai para `sessionStorage` no app).
- Cobertura mínima do pacote: 95% linhas e branches (limite configurado no Vitest).
- Comentários e mensagens de teste em pt-BR; identificadores de código em inglês.

## Review Focus

1. **Transcrição de fala com dígitos separados por espaço** ("meu CPF é 529 982 247 25"): esperado mascarar quando há contexto "CPF" logo antes. Teste no Task 3 (`cpf com espaços e contexto`).
2. **Números que não são dado pessoal** (valores `R$ 1.234.567,89`, número de processo CNJ `0001234-56.2026.8.26.0100`, horários `14h30`, datas `14/10/2026`, versões `2.3.4`, `ISO 9001`, `NR-5`): esperado **não** mascarar. Teste no Task 4 (`falsos positivos clássicos`).
3. **IA devolve marcador com outra grafia** (`[cpf_1]`, `[CPF 1]`, `[CPF-1]`): esperado reidratar mesmo assim e reportar como `malformedMarkers`. Testes nos Tasks 5 e 6.
4. **Mesmo CPF escrito de dois jeitos** (`529.982.247-25` e `52998224725`): esperado **um** marcador. Teste no Task 5 (`mesmo valor, formatos diferentes`).
5. **CNPJ alfanumérico em minúsculas** (`12.abc.345/01de-35`): esperado detectar (normaliza para maiúsculas). Teste no Task 2.

### Task 2: Normalização e detectores com DV (CPF, CNPJ, PIS, cartão)

**Files:**

- Create: `packages/pii-br/src/normalize.ts`, `packages/pii-br/src/context.ts`, `packages/pii-br/src/detectors/{cpf,cnpj,pis,cartao}.ts`, `packages/pii-br/src/detectors/types.ts`
- Test: `packages/pii-br/test/detectors-dv.test.ts`

**Interfaces:**

- Produces:
  ```ts
  // detectors/types.ts
  export interface Detector {
    type: PiiType;
    pattern: RegExp; // sempre com flag 'g'
    accept(raw: string, text: string, start: number): { ok: boolean; valid: boolean };
  }
  // normalize.ts
  export function normalizeValue(type: PiiType, raw: string): string;
  // context.ts
  export function hasContext(
    text: string,
    start: number,
    words: readonly string[],
    window?: number,
  ): boolean; // janela padrão 25, sem acento, sem caixa
  ```
- Regra de aceitação (vale para os 4): **com pontuação típica** (ex.: `529.982.247-25`, `11.222.333/0001-81`) → aceita mesmo com DV inválido (`valid: false`); **sem pontuação** → aceita só com DV válido **ou** com contexto. Palavras de contexto: CPF `['cpf']`; CNPJ `['cnpj']`; PIS `['pis', 'pasep', 'nit', 'nis']`; cartão `['cartao', 'cartão', 'credito', 'crédito']` (cartão **exige** Luhn válido sempre).
- Bordas: lookbehind/lookahead que impeçam casar dentro de sequência maior de dígitos/letras (`(?<![0-9A-Za-z])` … `(?![0-9A-Za-z])`).
- CPF com espaços (`529 982 247 25`) só com contexto.
- CNPJ: aceita minúsculas na entrada; `normalizeValue('CNPJ', …)` remove pontuação e põe em maiúsculas.
- `normalizeValue`: CPF/PIS/CARTAO → só dígitos; CNPJ → `[0-9A-Z]`; EMAIL → minúsculas; TELEFONE → só dígitos sem `55` inicial quando tiver 12–13 dígitos; CEP → dígitos; PLACA → maiúsculas sem hífen; RG → `[0-9X]` maiúsculo.

### Task 5: `mask()` / `unmask()` com `MaskMap`

**Files:**

- Create: `packages/pii-br/src/mask.ts`; Modify: `packages/pii-br/src/index.ts`
- Test: `packages/pii-br/test/mask.test.ts`

**Interfaces:**

- Produces:
  ```ts
  export function createMaskMap(): MaskMap; // { version: 1, markers: {}, keys: {}, counters: {} }
  export function mask(
    text: string,
    options?: DetectOptions & { map?: MaskMap },
  ): { masked: string; map: MaskMap; findings: Finding[] };
  export function unmask(text: string, map: MaskMap): string;
  export const MARKER_PATTERN: RegExp; // canônico: /\[([A-Z]+)_(\d+)\]/g
  ```
- `mask` **não muta** o mapa recebido; devolve um novo. Chave interna: `` `${type}:${normalizeValue(type, raw)}` ``. `markers[marcador]` guarda o **primeiro** texto original visto.
- `unmask` é tolerante: reconhece `/\[\s*([A-Za-z]+)[\s_-]?(\d+)\s*\]/g`, monta o canônico (`TIPO` em maiúsculas + `_N`) e troca se existir no mapa; caso contrário mantém o texto como está.

it('mesmo valor, formatos diferentes', () => {

**Interfaces:**

- Produces: `export function validateOutput(output: string, map: MaskMap, originalInput: string): OutputReport`
  - `unknownMarkers`: marcadores (canônicos ou tolerantes) que **não** existem no mapa, em forma canônica, sem repetição.
  - `malformedMarkers`: marcadores existentes no mapa mas escritos fora do formato canônico, como apareceram.
  - `newIdentifiers`: `detect(output)` cujos valores normalizados não aparecem em `detect(originalInput)`.
